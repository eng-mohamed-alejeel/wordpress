# تشغيل الكاش والإبطال — Auto Dealership Core

## الحالة المعتمدة

تستخدم الإضافة `AutoDealership\Cache\CacheManager` كنقطة موحدة للتعامل مع كاش الصفحات العامة. لا تستدعي الوحدات مزوّدًا بعينه مباشرة، باستثناء fallback التوافق الموجود في الثيم عندما لا تكون الإضافة محملة.

يدعم الحد المركزي:

- إبطال كاش منشور محدد عند تغير السيارة أو العرض.
- إبطال URL محدد عبر W3 Total Cache وLiteSpeed والـ hooks الخارجية.
- إبطال شامل فقط عند تغير إعدادات تؤثر في الموقع كله مثل الهوية والألوان والمحتوى العام.
- تسجيل آخر عملية إبطال دون تخزين الروابط أو بيانات العملاء.
- متابعة مزوّدي الكاش وحالة مهمة مزامنة انتهاء العروض من صفحة التشخيص.

لا تستخدم `wp_cache_flush()` في عمليات الحفظ العادية؛ فهو يمسح كاش الكائنات بالكامل وقد يسبب ضغطًا غير ضروري على قاعدة البيانات.

## انتهاء العروض

توجد طبقتان متكاملتان:

1. حدث Cron خاص بكل عرض عند تاريخ الانتهاء.
2. مراجعة يومية احتياطية تعالج الأحداث التي لم تُنفذ بسبب توقف Cron أو انقطاع مؤقت.

عند الانتهاء يتم إبطال صفحة العرض، السيارة المرتبطة، الأرشيف، الصفحة الرئيسية، وخرائط Sitemap ذات الصلة. كما تحدد صفحة العرض النشطة عمرًا أقصى حتى حد الانتهاء، بينما تستخدم الصفحة المنتهية عمرًا قصيرًا.

## إعداد Cron على الاستضافة

يفضل عند تفعيل `DISABLE_WP_CRON` في `wp-config.php` تشغيل WP-Cron من Cron النظام كل خمس دقائق عبر WP-CLI:

```text
*/5 * * * * cd /absolute/path/to/wordpress && wp cron event run --due-now --quiet >/dev/null 2>&1
```

إذا لم يتوفر WP-CLI، يمكن استخدام طلب HTTP:

```text
*/5 * * * * curl -fsS 'https://example.com/wp-cron.php?doing_wp_cron' >/dev/null 2>&1
```

يجب استبدال المسار والنطاق بالقيم الفعلية، وعدم استخدام `localhost` في الاستضافة. تظهر حالة المهمة في صفحة التشخيص تحت `Offer cache reconcile`.

## ربط CDN اختياريًا

يمكن ربط CDN خارجي دون تعديل منطق الإضافة عبر hooks التالية:

```php
add_action( 'adc_cache_purge_urls', function ( $urls, $post_ids, $context ) {
	// استدعاء API مزود CDN هنا بعد إضافة مفاتيح API في إعدادات الخادم.
}, 10, 3 );

add_action( 'adc_cache_purge_all', function ( $reason ) {
	// تنفيذ purge شامل لدى CDN عند الحاجة فقط.
}, 10, 1 );
```

يجب ألا تُحفظ مفاتيح CDN داخل ملفات الإضافة أو الثيم، كما يجب تقييد الإبطال الشامل للحالات الضرورية.

## فحص ما قبل النشر

- التأكد من ظهور مزوّد الكاش المتوقع في صفحة التشخيص.
- التأكد من وجود موعد تالٍ لـ `adc_offer_cache_reconcile`.
- تعديل عرض تجريبي وانتظار تسجيل `offer_change` في آخر Purge.
- اختبار انتهاء عرض في بيئة staging والتأكد من اختفاء نموذج الطلب وبيانات العرض التجارية.
- اختبار الصفحة الرئيسية والأرشيف وSitemap بعد تغيير الهوية أو المحتوى.
- عدم تشغيل أكثر من مزوّد Full-Page Cache دون سبب تشغيلي واضح.
