# إعداد البريد واختباره

يُدار الإرسال عبر `wp-content/mu-plugins/autobrands-mail.php` لجميع استدعاءات `wp_mail()`؛ لا يلزم تفعيل إضافة من لوحة التحكم. يشمل ذلك بريد WordPress ورسائل المتابعات وإشعارات WP Super Cache. لم تُغيّر إعدادات تشغيل بريد المتابعات، الذي يُدار بالخيار `adc_followup_email_enabled` وله طابور إرسال قائم.

## البيئة المحلية

يحتوي `wp-config.php` المحلي فقط على:

```php
define( 'WP_ENVIRONMENT_TYPE', 'local' );
define( 'ADC_MAIL_MODE', 'mailpit' );
```

تشغيل Mailpit في PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-mailpit.ps1 -Install
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-mailpit.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/stop-mailpit.ps1
C:\xampp\php\php.exe tools/test-local-mail.php
```

التثبيت يستخدم الإصدار المثبت `v1.31.5` من المستودع الرسمي، ويتحقق من SHA256 المعلن في GitHub. البرنامج والرسائل والسجلات محفوظة في `%LOCALAPPDATA%\AutoBrands\Mailpit` خارج مجلد الويب. يُشغّل كعملية مخفية، ويحتاج تشغيلًا مجددًا بعد إعادة تشغيل Windows. لا توجد إعادة توجيه أو ترحيل للبريد إلى الخارج.

واجهة الرسائل: http://127.0.0.1:8025، وخادم SMTP: `127.0.0.1:1025`. يحتفظ بما يصل إلى 500 رسالة. حذف الرسائل التجريبية يتم من واجهة Mailpit. إعداد التشغيل يتوافق مع [توثيق Mailpit الرسمي](https://mailpit.axllent.org/docs/configuration/).

الاختبار يرسل رسالتين اصطناعيتين، ويفحص الالتقاط والعربية وRTL والمرفق والروابط والفشل عند انقطاع SMTP. لا يُنشئ حسابات ولا يرسل رسائل لمستخدمين فعليين.

### نتيجة التنفيذ المحلي — 14 أكتوبر 2026

تم تثبيت Mailpit والتحقق من بصمة الأرشيف وتشغيله وربط WordPress به. نجح اختبار التكامل: التقاط رسالتين لكل تشغيل، صحة المرسل وReply-To، العربية واتجاه RTL، المرفق ورابط الاستعادة، إرجاع الفشل عند تعذر اتصال SMTP، ومنع الإرسال عند التعطيل أو نقص إعدادات SMTP. نجح فحص صياغة PHP وفحص اختلافات Git. رسائل الفشل الظاهرة أثناء الاختبار متعمدة.

اختبار رسالة المتابعة هنا اصطناعي عبر نفس مسار `wp_mail()`؛ لم يُشغّل طابور المتابعات الفعلي ولم يُنفّذ استعادة كلمة مرور لحساب قائم. SMTP الخارجي وتوثيق النطاق ووصول البريد الفعلي لم تُختبر بعد لعدم توفر بيانات المزود.

## SMTP الحقيقي والانتقال للنشر

### تجربة Gmail محليًا

تم تجهيز `tools/configure-gmail.ps1` للحساب `mohamedipos@gmail.com`. شغله من PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\xampp\htdocs\wordpress\tools\configure-gmail.ps1
```

أدخل كلمة مرور تطبيق جديدة في المطالبة المخفية. لا تستخدم كلمة مرور سبق مشاركتها في المحادثة. يتحقق السكربت من اتصال TLS ومصادقة Gmail دون إرسال رسالة، ثم يحفظ الإعدادات خارج مجلد الموقع داخل `%LOCALAPPDATA%\AutoBrands\MailCredentials` بصلاحيات مقيدة ويحدث إعداد البريد المحلي. يجب تشغيل Apache تحت حساب Windows نفسه أو إعطاء حساب الخدمة صلاحية قراءة الملف بشكل مقصود. لا تنقل هذا الإعداد المحلي إلى الإنتاج.

بعد نجاح التفعيل، تصبح رسائل النظام الجديدة ومهام البريد المستحقة قابلة للإرسال الحقيقي. لا يشغّل السكربت الطابور بنفسه، ولا يعيد إرسال الحملات المكتملة. لا يثبت اختبار المصادقة وصول الرسائل إلى الوارد. حساب Gmail ليس ربطًا بإشعارات تسليم أو ارتداد من مزود حملات.

للعودة إلى Mailpit دون حذف بيانات الدخول:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\xampp\htdocs\wordpress\tools\configure-gmail.ps1 -Mailpit
```

### قالب استعادة كلمة المرور

يضيف `autobrands-password-email.php` قالب HTML عربيًا باتجاه RTL، وقالبًا إنجليزيًا حسب لغة رسالة WordPress. يستخدم اسم الموقع وألوانه من `car_dealer_theme_settings`، وزر تعيين كلمة مرور جديدة، ورابطًا بديلًا قابلًا للنسخ، وتنبيهًا لتجاهل الطلب غير المقصود. لا يعرض اسم المستخدم التقني أو عنوان IP. توجد نسخة نصية بديلة، ولا يتغيّر تنسيق الرسائل الأخرى.

تم اختبار العربية والإنجليزية والإبقاء على معاملات مفتاح الاستعادة واسم المستخدم في الرابط، والالتقاط في Mailpit وعدم انتقال تنسيق HTML إلى الرسائل التالية. رسائل المعاينة المرسلة إلى `qa@autobrands.test` تستخدم مفتاحًا اصطناعيًا غير صالح للاستعادة. للاختبار الفعلي اطلب «نسيت كلمة المرور» مرة أخرى؛ الرسائل القديمة تبقى بتنسيقها السابق. أُدرج القالب في حزمة الإصدار.

في البيئة التجريبية اضبط `WP_ENVIRONMENT_TYPE` على `staging`، وفي الإنتاج على `production`. اضبط القيم التالية من متغيرات بيئة عملية PHP/Apache أو ثوابت في `wp-config.php` غير المتتبع. متغيرات البيئة لها الأولوية، وتحتاج إعادة تشغيل Apache عند تغيير بيئته.

| المتغير | القيمة |
|---|---|
| `ADC_MAIL_MODE` | `smtp` |
| `ADC_SMTP_HOST` | اسم خادم المزود |
| `ADC_SMTP_PORT` | منفذ المزود، عادة 587 أو 465 |
| `ADC_SMTP_ENCRYPTION` | `tls` لـ STARTTLS أو `ssl` لاتصال TLS مباشر |
| `ADC_SMTP_USERNAME` | اسم المستخدم من المزود |
| `ADC_SMTP_PASSWORD` | كلمة مرور أو مفتاح SMTP، خارج المستودع |
| `ADC_MAIL_FROM` | عنوان مُوثّق لدى المزود |
| `ADC_MAIL_FROM_NAME` | اسم المرسل، افتراضيًا AutoBrands |

لا يُسمح لـ Mailpit في staging أو production. الإعداد الافتراضي عند غياب الضبط هو تعطيل الإرسال مع تنبيه للمدير؛ لا يوجد رجوع تلقائي إلى PHP mail. تُحفظ عناوين Reply-To التي يحددها النظام، ويُوحّد عنوان From. تحقق TLS يبقى مفعّلًا. السجلات تسجّل كود الخطأ فقط دون محتوى الرسائل أو بيانات الاعتماد.

قبل النشر: وفّر بيانات المزود ونطاق الإرسال، واضبط SPF وDKIM وDMARC حسب تعليماته، ثم اختبر استعادة كلمة المرور لحساب اختبار وإشعار إنشاء الحساب ورسالة متابعة حقيقية في staging باستخدام مستلمين معتمدين. افحص الوارد والبريد المزعج والارتداد وسجلات المزود والروابط والتنسيق. نجاح `wp_mail()` يعني قبول SMTP للرسالة، ولا يثبت الوصول إلى الوارد.

تجنب تشغيل إضافات SMTP أخرى بالتزامن. لا تفعّل الإرسال الجماعي أو طابور المتابعات في staging قبل ضبط المستلمين التجريبيين. إعادة المحاولة تتبع طابور المتابعات القائم؛ بريد WordPress المباشر لا يملك إعادة محاولة مضافة هنا.

للرجوع: أعد إعدادات مزود صالح سابقة؛ ويمكن استخدام `ADC_MAIL_MODE=disabled` لإيقاف البريد مؤقتًا. إعداد wp-config السابق محفوظ محليًا في `%LOCALAPPDATA%\AutoBrands\ConfigBackups`. لا تنسخ الإعداد المحلي إلى الإنتاج. أُضيف ملف إعداد البريد إلى مسارات حزمة الإصدار.
