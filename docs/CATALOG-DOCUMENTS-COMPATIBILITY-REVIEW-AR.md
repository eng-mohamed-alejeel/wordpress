# مراجعة إصلاح الكتالوج واستجابات السجلات المحمية

التاريخ: 2026-10-20. مرجع البداية: `692ef54`.

## السبب الجذري

- اختبار الكتالوج يقيس الصفحة والإجمالي والفلاتر لبيانات اصطناعية تضم 240 سيارة. بلغ التنفيذ 66 استعلامًا، منها 49 إلى جدول الموديلات. فحص ارتباط الموديل من مرشح الصورة كان يتكرر لكل سيارة. الحد الأصلي هو 25 استعلامًا.
- مسار مستندات أونكس يفحص البيع المطلوب بعد بدء إخراج الصفحة. كان البيع غير المسموح يُرفض، لكن الاستجابة قد تبقى HTTP 200 بعدما تُرسل الترويسات. كشف الاختبار ذلك على PHP 8.0.
- بعد تجاوز اختبار الكتالوج، كشفت الحزمة الكاملة النمط نفسه في صفحة تفاصيل أوامر الشراء للمستخدم الذي لا يملك نطاق الفرع.

## التغييرات

- `GroupedModelCatalog.php`: جلب ارتباطات سيارات الصفحة دفعة واحدة، بما فيها النتائج غير المرتبطة. تنتهي لقطة الارتباطات بانتهاء بناء القائمة، وتُستعاد الحالة السابقة داخل `finally` حتى عند وقوع استثناء؛ لا يوجد كاش دائم يحتاج إبطالًا عند تعديل المخزون.
- `PublicCatalog.php`: بناء حقول القائمة ضمن هذه اللقطة، مع إبقاء حساب السعر والعنوان والرابط والصورة والترتيب كما هي.
- `OnyxDocuments.php` و`PurchaseOrderPage.php`: فحص صلاحية قراءة السجل قبل أي إخراج من الدالة التي تعرض الصفحة.
- `Navigation.php`: تسجيل الفحص أيضًا في حدث `load-<page hook>` حتى يسبق ترويسة إدارة WordPress الحقيقية.
- اختبارات الأداء: إبقاء السقف الأصلي، ومقارنة جميع حقول صفحات 12 و24 و48 سيارة، وفحص النتائج المرتبطة وغير المرتبطة والتخلص من اللقطة عند الاستثناء وبعد تعديل الارتباط.
- اختبارات HTTP: إيقاف تخزين المخرجات مؤقتًا في خادم اختبار الداشبورد، والتحقق من 404 وغياب بيانات المستند الأجنبي وعدم تعديل البيع أو المستند، مع استمرار وصول الأدمن المصرح له. تقوية تحقق رفض أمر الشراء ليشمل عدم عرض رقمه أو نماذج إجراءاته.
- `quality.yml`: تشغيل وظيفتي الاختبار على PHP 8.0 و8.2 عبر `matrix.php` الفعلي، وإضافة الحزمة المعزولة الكاملة إلى CI، والتصريح بامتداد cURL اللازم لها. لم تُعطّل اختبارات أو تُتجاهل رموز خروج.

## نتائج التحقق المحلية

استُخدم PHP 8.0.30 وPHP 8.2.12 فعليًا، مع MariaDB معزول على المنفذين 33369 و33370. لم يُحمّل وضع `--isolated` إعدادات قاعدة بيانات الموقع، ولم تُرسل رسائل بريد حقيقية.

| الفحص | PHP 8.0.30 | PHP 8.2.12 |
| --- | --- | --- |
| مجموعات CI المستقلة السبع، ومنها 120 تحققًا للإعدادات | ناجح | ناجح |
| صياغة 454 ملف PHP للإضافة والثيم | ناجح | ناجح |
| الداشبورد والتنقل ومستندات أونكس: 115 تحققًا | ناجح | ناجح |
| الحساب: 230 تحققًا | ناجح | ناجح |
| العملة: 45 تحققًا | ناجح | ناجح |
| المصادقة: 34 تحققًا | ناجح | ناجح |
| الحزمة الكاملة `database-runner.php --isolated` | ناجح | ناجح |
| قياس الكتالوج بعد الإصلاح | 19 استعلامًا | 19 استعلامًا |

نجح فحص CSS واتساق النصوص، وفحص صياغة ملفات PHP المعدلة بعد آخر تغيير. انتهى Intelephense 1.18.5 دون أخطاء في الكود المملوك للمشروع. جرى تحليل YAML والتحقق من ربط إعداد PHP بمصفوفة الإصدارين ومن غياب `continue-on-error`.

السجلات المحلية موجودة تحت `.tmp/php-compatibility/`، ومنها `workspace-final-8.0.log` و`workspace-final-8.2.log` و`full-final-8.0.log` و`full-final-8.2.log` وملفات نتائج JSON.

لا توجد تغييرات في مخطط البيانات أو قواعد الصلاحيات أو تنسيقات السعر أو عمليات إصدار المستندات. التغيير في السجلات غير المسموحة هو تقديم الرفض قبل إخراج الصفحة لضمان رمز HTTP الصحيح. لا يُعد نجاح الفحوص المحلية إثباتًا لتشغيل GitHub Actions عن بُعد؛ يلزم رفع التغييرات لتشغيل الوظائف هناك.
