# خطة الأدوار والصلاحيات

1. اعتماد أدوار المعرض الحالية كقوالب افتراضية، مع بقاء معرفاتها ثابتة وترجمة أسمائها حسب لغة المستخدم العربية أو الإنجليزية.
2. توحيد قائمة الصلاحيات القابلة للتعيين وإظهارها في مجموعات: مساحة العمل، العملاء والمبيعات، المخزون والمشتريات، المالية، التقارير والرقابة، وكتالوج الموقع.
3. إضافة مربعات اختيار في صفحة تحرير المستخدم. تفعيل التخصيص يحفظ مجموعة صريحة من السماح والمنع؛ تعطيله يزيل الاستثناءات ويعيد توريث صلاحيات الدور، بما فيها أي تعديلات مستقبلية عليه.
4. قصر إدارة الاستثناءات على مسؤول النظام المخول بتحرير المستخدم وترقية الأدوار. حماية حسابات المسؤول ورفض الطلبات المزورة والصلاحيات غير المدرجة، وعدم إدراج صلاحيات إدارة WordPress أو الصلاحيات التي تتطلب معرف محتوى.
5. استخدام صلاحيات WordPress الأصلية حتى تسري الإعدادات على الواجهة والخدمات وREST. تبقى حدود الفروع والتحقق من العمليات المالية كما هي؛ منح صلاحية إجراء لا يوسع نطاق الفروع.
6. التحقق من البيانات قبل حفظ الملف، ثم حفظ الصلاحيات بعد نجاح تحديث المستخدم. تسجيل التغيير عبر SecurityAudit الحالي بتحديث واحد لبيانات الصلاحيات.
7. التحقق من الترجمة وتغطية القائمة، ومنح الصلاحية وسحبها والعودة للدور، ورفض محاولات رفع الصلاحيات وحماية المسؤول. تشغيل اختبارات توافق مساحة العمل والأدوار.

## طريقة الاستخدام

المستخدمون ← تحرير المستخدم ← صلاحيات المستخدم. فعّل «تخصيص صلاحيات هذا المستخدم»، وحدّد الصلاحيات المطلوبة، ثم اضغط «تحديث المستخدم». لإعادة صلاحيات الدور ألغِ تفعيل التخصيص واحفظ.

عند تفعيل التخصيص تبقى الاختيارات صريحة حتى عند تغيير الدور؛ ألغِ التخصيص إذا أردت تطبيق الدور الجديد. يحتاج الموظف إلى صلاحية دخول مساحة العمل وصلاحيات الإجراءات المناسبة، وإلى تعيين فرع عبر إعدادات الفروع الحالية.

يمكن تخصيص الصلاحيات أثناء إضافة الحساب أو بعد إنشائه، وتظهر معاينة صلاحيات الدور تحت حقل الدور في الإضافة والتحرير. تحت إعدادات المنصة ← الأدوار والصلاحيات يمكن تعديل صلاحيات المعرض لأي دور غير مسؤول النظام، أو إنشاء دور جديد بمعرّف يبدأ بـ `adc_role_` واسمين بالعربية والإنجليزية.

تغييرات الدور تسري على المستخدمين الذين يرثون صلاحياته؛ من فعّل تخصيصًا فرديًا يبقى ضمن الصلاحيات المحددة له. عند تغيير الدور مع تعطيل التخصيص تتحدّث الاختيارات إلى افتراضيات الدور الجديد. تحفظ تعريفات الأدوار المخصصة حتى لا يعيد تحديث الإضافة الصلاحيات الملغاة. تُسجل تغييرات الأدوار في سجل التدقيق الحالي.

إدارة الأدوار تخص صلاحيات المعرض وكتالوجه؛ تبقى صلاحيات WordPress الأصلية للأدوار الحالية محفوظة، ويبدأ الدور الجديد بصلاحية القراءة وصلاحيات المعرض المختارة فقط. حسابات ودور مسؤول النظام محمية. تخصيص المستخدم أثناء الإضافة يستخدم مسار إنشاء الحساب المعتاد في الموقع الحالي؛ مسارات الدعوة والتسجيل المؤجل في WordPress Multisite لا تعرض هذا التخصيص.
