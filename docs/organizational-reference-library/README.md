# مكتبة مرجعية محايدة للأدوار والمسؤوليات والضوابط

## الغرض

توفر هذه المكتبة نقطة بدء قابلة لإعادة الاستخدام لبناء الهيكل الوظيفي، والأوصاف الوظيفية، ومصفوفات الصلاحيات، وإجراءات العمل في منشآت مختلفة. وهي ليست هيكلًا تنظيميًا جاهزًا لشركة بعينها، ولا سياسة تشغيل نافذة، ولا رأيًا قانونيًا.

## طبقات الاستخدام

1. **المرجع العام:** مبادئ الحوكمة، تعريف الوظائف والمسؤوليات، أقل صلاحية، فصل الواجبات، التوثيق والمراجعة.
2. **حزمة القطاع:** أنماط ومخاطر وخطوات خاصة بنشاط معين. حزمة تجارة السيارات اختيارية ومنفصلة في [حزمة تجارة السيارات](./industry-packs/automotive-retail-ar.md).
3. **ملف المنشأة:** الهيكل الفعلي، والمسميات، والمواقع، والحدود المالية، والموافقون، ومدد الاحتفاظ، والمتطلبات النظامية التي تعتمدها المنشأة المخولة. لا تملأ المكتبة العامة هذه القيم نيابة عنها.
4. **إعداد المنتج التقني:** ربط القرارات المعتمدة فقط بالقدرات والإعدادات التي يدعمها البرنامج بعد التحقق والاختبار. لا يحول المسمى الوظيفي تلقائيًا إلى حساب WordPress أو صلاحية.

## دليل الملفات

- [نموذج الوظائف والمسؤوليات](./organization-model-ar.md): وظائف تنظيمية مرنة، بصرف النظر عن مسميات المنشأة أو حجمها.
- [قالب الوصف الوظيفي](./job-description-template-ar.md): قالب لتحديد غرض الوظيفة ومسؤولياتها وحدودها ومؤشراتها.
- [قالب التفويض والفصل والضوابط](./delegation-and-control-template-ar.md): مصفوفة طلب/تنفيذ/اعتماد/مراجعة، وتحليل تعارض الواجبات.
- [قالب السياسات والإجراءات والنماذج](./policy-sop-forms-template-ar.md): بنية قابلة للتعبئة لدورة السياسة والإجراء والنموذج.
- [حزمة تجارة السيارات](./industry-packs/automotive-retail-ar.md): تطبيق اختياري للمبادئ العامة على عمليات تجارة السيارات.
- [مصفوفة تتبّع المصادر](./source-traceability-ar.md): تربط الوثائق الأصلية بالمحتوى العام والقطاعي وقرارات المنشأة والمواد المستبعدة.
- [مثال تعبئة خيالي](./fictional-worked-example-ar.md): يشرح كيفية تعبئة القوالب دون وضع حدود أو صلاحيات افتراضية.
- تعرض صفحة **الأدوار والصلاحيات** في لوحة تحكم الإضافة خريطة مرجعية لثماني وظائف تنظيمية وقدرات الإضافة الحالية المرتبطة بها. يمكن حفظ اختيار الوظائف مع الدور بوصفه مرجع مواءمة فقط، وتصفية قائمة القدرات المرتبطة بها؛ ولا يؤدي الاختيار أو التصفية إلى تحديد صلاحيات أو منحها. تعرض مراجعة الوظيفة حالة كل قدرة مرتبطة بها (محددة يدويًا أو غير محددة)، وتؤكد أن عدم التحديد ليس توصية بالمنح. ويعرض تقرير مقارنة للقراءة فقط عدد القدرات المرتبطة المحددة يدويًا وغير المحددة، ويسرد الصلاحيات المختارة خارج الوظائف المختارة؛ التقرير يقارن افتراضيات الدور ولا يشمل الاستثناءات الفردية أو المنح المؤقتة أو نطاق البيانات. وعند وجود قدرات محددة خارج التصفية، توضح الصفحة أنها ستبقى دون تغيير. يجب اختيار القدرات اللازمة لكل مهمة يدويًا ثم مراجعة أثر التغيير ونطاقه والتعارضات قبل الحفظ.

## طريقة تطبيقها على منشأة

1. حدد نشاط المنشأة وكياناتها ومواقعها ونمط استخدامها للمنتج.
2. اختر الوظائف التي تحتاجها فعلًا؛ لا تفترض أن كل منشأة تحتاج إدارة أو منصبًا مستقلًا لكل وظيفة مرجعية.
3. اربط الوظائف بمسؤوليات وعمليات وبيانات واضحة، ثم عيّن أصحاب القرار والمراجعين بموجب تفويض موثق.
4. املأ الحدود والقيم والتواريخ والاستثناءات بعد قرار أصحاب الصلاحية، واتركها «غير محددة» إلى حين الاعتماد.
5. افحص تعارض المهام؛ إذا تعذر الفصل في منشأة صغيرة، وثّق تعارض الأدوار والضابط التعويضي ومراجعه ومدة العمل به.
6. قارن كل صلاحية رقمية بمهمة فعلية وبياناتها ونطاقها، ولا تستنتجها من اسم المنصب.
7. اختبر حالات السماح والرفض ونطاق السجلات قبل تفعيل أي إعداد تقني.
8. راجع الوثائق عند تغير النشاط أو الهيكل أو الأنظمة أو المخاطر، وسجل الإصدار والاعتماد.

## ما لا تمثله هذه المكتبة

- الأدوار الواردة أمثلة وظيفية وليست قائمة إلزامية أو هيكلًا تنظيميًا مفروضًا.
- أي حد مالي أو مدة أو نسبة أو KPI يجب أن يقرره مالك العمل لكل منشأة؛ لا توجد قيمة افتراضية هنا.
- اعتماد منشأة لا ينتقل إلى منشأة أخرى.
- ملف الحوكمة أو القالب المنشور لا يغير وحده صلاحيات النظام.
- الأدوار التنظيمية، وأدوار WordPress، والقدرات التقنية، ونطاق الوصول مفاهيم مترابطة لكنها غير متطابقة.
- تطبيق هذه القوالب لا يثبت دعم عدة شركات مستقلة داخل تثبيت WordPress مشترك.

## مرجعية المنتج

يمكن استخدام [سجل قرارات الصلاحيات والخصوصية](../AUTHORIZATION-POLICY-PRIVACY-SIGNOFF-AR.md) لتسجيل قرارات مستقلة لكل تثبيت، مع إبقاء أساس الأمان منفصلًا عن قرارات الأعمال. تظل الخيارات التي لا ينفذها المنتج حاليًا قرارات موثقة أو فجوات تطوير، ولا يجوز عرضها للمستخدم كأنها مطبقة تقنيًا.
