# خطة تحسين SEO احترافية وشاملة

**المشروع:** Auto Dealership / Car Dealer  
**تاريخ إعداد الخطة:** 2026-10-26  
**الحالة:** جاهزة للتنفيذ على مراحل  
**النطاق:** الموقع العام، كتالوج السيارات، العروض، الصفحات التحريرية، اللغتان العربية والإنجليزية، المشاركة، Sitemap، البيانات المنظمة، والأداء التقني، مع توليد SEO ديناميكي لكل تثبيت مستقل.

**نموذج التشغيل المعتمد:** كل شركة لها تثبيت WordPress وقاعدة بيانات مستقلان. لا يوجد مخزون أو محتوى أو إعدادات SEO مشتركة بين الشركات داخل نفس قاعدة البيانات.

## 1. الهدف

إنشاء عقد SEO موحد وقابل للصيانة داخل كل تثبيت، يجعل الموقع:

- قابلًا للاكتشاف والفهرسة دون صفحات مكررة أو روابط داخلية قديمة.
- واضحًا لمحركات البحث في أنواع المحتوى: سيارة، عرض، كتالوج، صفحة تحريرية.
- صحيحًا في العربية والإنجليزية مع Canonical وHreflang متبادلين.
- غنيًا بالبيانات المنظمة دون ادعاءات غير موجودة في بيانات السيارة.
- سريعًا وقابلًا للقياس على الهاتف وسطح المكتب.
- متوافقًا مع روابط السيارات والعروض الجديدة والروابط القديمة المحولة.
- قابلًا للتراجع دون تعديل مدمر لقاعدة البيانات.
- مولدًا لعناصر SEO تلقائيًا من إعدادات الشركة ومحتوى التثبيت، مع إمكانية التخصيص اليدوي.

## 2. نتائج المراجعة الحالية

تمت مراجعة صفحات محلية فعلية في 2026-10-26، وكانت النتائج التالية:

| المجال | الحالة الحالية | التقييم |
|---|---|---|
| عنوان الصفحة | موجود عبر `title-tag` | جيد، يحتاج قوالب أكثر دقة |
| Meta Description | غير موجود في الصفحات المفحوصة | فجوة P0 |
| Canonical | موجود في الصفحة الرئيسية والصفحات المفردة والعروض، وغير مكتمل في أرشيف السيارات الافتراضي | فجوة P0 |
| Hreflang | موجود بثلاثة روابط `ar`, `en`, `x-default` | يحتاج تحققًا متبادلًا وقواعد أوضح |
| Open Graph | غير موجود | فجوة P1 |
| Twitter/X Cards | غير موجود | فجوة P1 |
| JSON-LD | Organization عام، وVehicle في بعض الصفحات المفردة | يحتاج Graph كاملًا وBreadcrumb وItemList |
| Sitemap | WordPress core ينشئ Sitemap للسيارات والعروض والتصنيفات | يحتاج ضبط الأهلية والاستبعاد |
| روابط السيارات والعروض | الروابط الجديدة ASCII وثابتة، والقديمة تعمل بتحويل 301 | جيد، يجب تثبيته باختبارات SEO |
| الفلاتر | الفلاتر النشطة تحصل على `noindex, follow` في وضع الكتالوج الموثوق | يحتاج Canonical واضحًا ومنع تسرب صفحات البحث |
| المشاركة | تستخدم الرابط النظيف الناتج من `get_permalink()` | جيد، يحتاج اختبارًا صريحًا ضد الروابط القديمة |
| الحسابات والإدارة | ليست جزءًا من المحتوى العام المقصود للفهرسة | يجب تثبيت `noindex` وعدم إدراجها في Sitemap |

النتيجة: أساس الروابط جيد، لكن طبقة SEO الوصفية والفهرسة المنظمة ما زالت غير مكتملة.

## 3. نموذج البيانات الديناميكي لكل شركة

بما أن كل شركة مستقلة بقاعدة بياناتها، فإن مصدر SEO يكون محليًا داخل التثبيت نفسه:

### 3.1 إعدادات الشركة

تُقرأ من إعدادات الموقع المعتمدة، مثل:

- اسم الشركة والمعرض.
- الشعار والهوية البصرية.
- المدينة والدولة.
- الفروع العامة المنشورة.
- بيانات التواصل العامة.
- اللغة الافتراضية واللغة البديلة.
- النطاق العام وHTTPS.
- وصف النشاط المعتمد.

لا يتم وضع اسم شركة أو مدينة أو هاتف ثابت داخل القوالب البرمجية. كل تثبيت يولّد النتائج من إعداداته الخاصة.

### 3.2 بيانات المحتوى

- السيارة: الماركة، الموديل، الفئة، السنة، الحالة، الموقع، السعر، الصورة، والميزات المتاحة.
- العرض: العنوان، السيارة المرتبطة، السعر، الخصم، تاريخ الانتهاء، والصورة.
- الصفحة التحريرية: العنوان والوصف المعتمد والمحتوى المنشور.
- العلامة أو التصنيف: الاسم والوصف وعدد العناصر المؤهلة.

### 3.3 أولوية القيم

```text
قيمة SEO يدوية معتمدة للصفحة
        ↓
قيمة مولدة من بيانات المحتوى وإعدادات الشركة
        ↓
قالب افتراضي آمن من إعدادات التثبيت
```

إذا كانت معلومة أساسية ناقصة، لا يتم اختراعها؛ يستخدم النظام fallback واضحًا أو يمنع الفهرسة عند الحاجة.

### 3.4 العزل بين الشركات

لا نحتاج إلى Tenant ID أو عزل داخلي بين الشركات لأن كل شركة تملك قاعدة بيانات مستقلة. لكن يجب ضمان:

- عدم وجود اسم شركة افتراضي داخل الكود.
- عدم وجود نطاق أو هاتف أو مدينة ثابتة في البيانات المنظمة.
- عدم نسخ Cache أو Sitemap أو إعدادات SEO بين تثبيتين.
- إنشاء كل حزمة نشر من الكود نفسه مع إعدادات الشركة من بيئتها.
- اختبار أن `home_url()` وبيانات الموقع والـ Canonical تستخدم نطاق التثبيت الحالي.

## 4. مبادئ التنفيذ

1. لا نغير `post_name` ولا نعدل بيانات السيارات لمجرد SEO.
2. كل رابط عام يمر من عقد مركزي واحد، ولا يبنى من Slug داخل القوالب.
3. كل صفحة قابلة للفهرسة لها Title وDescription وCanonical وبيانات منظمة مناسبة.
4. كل صفحة غير مناسبة للفهرسة تحصل على سياسة صريحة: `noindex, follow` أو منع كامل حسب طبيعتها.
5. لا نضع في Schema معلومات غير مؤكدة أو أسعارًا منتهية أو بيانات شخصية.
6. لا نستخدم خدمات اختصار روابط خارجية للمشاركة.
7. نختبر المخرجات الفعلية من HTML، وليس الكود فقط.
8. كل مرحلة قابلة للتراجع ولا تتطلب ترحيلًا مدمرًا.

## 5. العقد المعماري المقترح

إضافة طبقة مركزية داخل الإضافة، مثل:

```text
src/SEO/PublicSeo.php
```

وتكون مسؤولة عن قراءة إعدادات التثبيت الحالي ومحتواه، ثم توليد:

- `document_title`.
- Meta Description.
- Canonical.
- Robots.
- Open Graph.
- Twitter/X Cards.
- Hreflang.
- JSON-LD.
- Breadcrumbs.
- سياسات Sitemap.
- كشف نوع الصفحة واللغة والمحتوى المؤهل.

لا تحتوي الخدمة على أسماء شركات أو محتوى تجاري خاص بشركة بعينها. ويمكن إضافة واجهة إعدادات SEO عامة لكل تثبيت، مثل:

- قالب Title.
- قالب Description.
- وصف الشركة الافتراضي.
- صورة المشاركة الافتراضية.
- إعدادات الفهرسة.
- الحقول اليدوية المعتمدة للصفحات.

يجب أن تستخدم هذه الطبقة خدمات القراءة الحالية مثل `PublicCatalog` و`PublicOfferView` و`CatalogPresentation`، وألا تنفذ استعلامات تجارية مكررة داخل `wp_head`.

## 6. بنية الفهرسة المستهدفة

### 6.1 صفحات قابلة للفهرسة

- الصفحة الرئيسية.
- أرشيف السيارات الافتراضي بدون فلاتر.
- أرشيف العروض الافتراضي.
- صفحة السيارة المنشورة والمؤهلة للعرض.
- صفحة العرض المنشور والساري.
- الصفحات التحريرية العامة مثل من نحن، تواصل معنا، التمويل، الأسئلة الشائعة، ودليل الشراء.
- صفحات العلامات أو التصنيفات فقط إذا كان لها محتوى فريد وعدد نتائج كافٍ.

### 6.2 صفحات غير قابلة للفهرسة

- تسجيل الدخول والتسجيل ولوحة حساب العميل.
- صفحات الإدارة وكل `wp-admin`.
- المقارنة الديناميكية.
- نتائج البحث الداخلية.
- صفحات الكتالوج التي تحتوي على فلاتر أو فرز أو معاملات مؤقتة.
- صفحات 404.
- العروض المنتهية أو غير المنشورة.
- السيارات غير المتاحة أو المسودة أو الخاصة.
- روابط الإجراءات، النماذج، والتنزيلات الخاصة.

السياسة الافتراضية للصفحات الديناميكية:

```text
noindex, follow
```

مع عدم إدراجها في Sitemap وعدم إنشاء Canonical يوهم بأنها صفحة مستقلة.

## 7. Metadata

### 7.1 Titles

قوالب قصيرة وفريدة، مع منع التكرار:

- الصفحة الرئيسية: `{اسم المعرض} | سيارات جديدة وعروض وتمويل`.
- أرشيف السيارات: `سيارات للبيع في {المدينة} | {اسم المعرض}`.
- السيارة: `{الماركة} {الموديل} {الفئة} {السنة} | {اسم المعرض}`.
- العرض: `{عنوان العرض} | عروض {اسم المعرض}`.
- الصفحات التحريرية: العنوان التحريري المعتمد فقط.

يجب ألا يعتمد Title على رقم المخزون أو السعر المتغير إلا عند الحاجة التجارية، لأن تغيّره المستمر يسبب ضوضاء في نتائج البحث. اسم المعرض والمدينة يأتيان من إعدادات التثبيت الحالي، لا من قيمة ثابتة في الكود.

### 7.2 Meta Description

توليد وصف فريد من 120 إلى 160 حرفًا تقريبًا، مع fallback آمن:

- السيارة: الماركة، الموديل، السنة، الحالة، السعر عند توفره، المدينة، ودعوة مختصرة للتواصل.
- العرض: اسم العرض، الفائدة، مدة الصلاحية إن كانت صالحة، والسيارة المرتبطة.
- الأرشيف: نوع السيارات، نطاق الخدمة، وإمكانية الفلترة.
- الصفحات التحريرية: وصف يدوي قابل للمراجعة.

لا يوضع رقم هاتف أو سعر غير مؤكد أو وعد غير موجود في البيانات.

### 7.3 Open Graph وTwitter/X

إضافة القيم التالية لكل صفحة عامة قابلة للمشاركة:

- `og:type`.
- `og:title`.
- `og:description`.
- `og:url` بالرابط Canonical النظيف.
- `og:image` بأبعاد فعلية مناسبة.
- `og:site_name`.
- `og:locale` و`og:locale:alternate`.
- `twitter:card=summary_large_image`.
- `twitter:title`.
- `twitter:description`.
- `twitter:image`.

يجب منع تكرار هذه الوسوم إذا أضافها قالب أو إضافة أخرى، مع توفير Filter تعطيل واضح للتوافق.

## 8. Canonical وHreflang

### 8.1 Canonical

- الصفحة المفردة Canonical إلى `/cars/car-{ID}/` أو `/offers/offer-{ID}/`.
- أرشيف السيارات الافتراضي Canonical إلى `/cars/`.
- أرشيف العروض الافتراضي Canonical إلى `/offers/`.
- الفلاتر والبحث والفرز: `noindex, follow` وCanonical إلى الأرشيف الأساسي أو عدم طباعة Canonical حسب نوع الطلب.
- إزالة معاملات التتبع من Canonical مثل `utm_*` و`fbclid`.
- الحفاظ على `lang=en` في Canonical للنسخة الإنجليزية فقط.
- الرابط القديم العربي لا يكون Canonical؛ يحول 301 إلى الرابط الجديد.

### 8.2 Hreflang

لكل صفحة قابلة للفهرسة:

```text
ar       النسخة العربية
en       النسخة الإنجليزية
x-default النسخة الافتراضية المعتمدة
```

يجب أن تكون الروابط متبادلة: صفحة العربية تشير إلى الإنجليزية، والإنجليزية تشير إلى العربية. إذا لم تتوفر ترجمة معتمدة للعنصر، لا ننشئ نسخة إنجليزية ضعيفة؛ نستخدم سياسة واضحة بدل صفحة شبه مكررة.

## 9. البيانات المنظمة JSON-LD

استخدام `@graph` موحد، مع `@id` ثابت لكل كيان.

### الصفحة الرئيسية

- `Organization` من اسم الشركة والنطاق والشعار وبيانات التواصل العامة للتثبيت الحالي.
- `WebSite`.
- `WebPage`.
- `SearchAction` فقط إذا كان بحث الموقع عامًا وقابلًا للزحف فعلًا.

### الصفحة المفردة للسيارة

- `WebPage`.
- `BreadcrumbList`.
- `Vehicle` مع البيانات المؤكدة فقط.
- `Offer` عند وجود سعر صالح.
- `ImageObject` عند توفر صورة صالحة.
- `seller` أو `brand` من بيانات المعرض المعتمدة.

حقول السيارة الممكنة عند توفرها:

```text
name
description
url
image
brand
model
vehicleConfiguration
vehicleModelDate
mileageFromOdometer
vehicleTransmission
fuelType
color
itemCondition
offers
```

### صفحة العرض

عدم تمثيل العرض كـ `Vehicle` وحده. الأفضل استخدام:

- `WebPage`.
- `BreadcrumbList`.
- `Product` أو كيان المركبة المرتبط.
- `Offer` بالسعر والعملة والصلاحية والرابط Canonical.

يجب حذف `priceValidUntil` إذا انتهت صلاحيته أو تحويل الصفحة إلى سياسة العرض المنتهي.

### أرشيف السيارات والعروض

- `CollectionPage`.
- `BreadcrumbList`.
- `ItemList` للعناصر الظاهرة في الصفحة الحالية.

لا نضع في Schema سيارات غير ظاهرة أو غير مؤهلة أو نتائج الفلاتر التي تحمل `noindex`.

## 10. Sitemap وRobots

### Sitemap

تخصيص WordPress Sitemap ليشمل فقط:

- السيارات المنشورة والمؤهلة للعرض العام.
- العروض المنشورة والسارية.
- الصفحات التحريرية المنشورة والمراجعة.
- التصنيفات والعلامات التي لها قيمة فعلية ومحتوى كافٍ.

واستبعاد:

- الحسابات، البحث، المقارنة، الفلاتر، المستخدمين، والمسودات.
- السيارات غير المتاحة حسب سياسة الكتالوج.
- العروض المنتهية.
- التصنيفات الفارغة أو الضعيفة.

إضافة `lastmod` من تاريخ تعديل فعلي ذي قيمة، وعدم تغيير التاريخ مع كل زيارة.

### Robots

- `robots.txt` يعلن Sitemap الرسمي.
- عدم منع CSS أو JavaScript أو الصور المطلوبة للرندر.
- منع مسارات الإدارة والمسارات الخاصة فقط.
- عدم الاعتماد على `robots.txt` وحده لمنع الفهرسة؛ صفحات الحسابات تستخدم `noindex` أيضًا.

## 11. المحتوى والربط الداخلي

- إضافة وصف فريد للسيارة عند توفره، مع عدم نشر وصف آلي فارغ.
- ربط السيارة بالعلامة والموديل والعروض ذات العلاقة.
- إضافة Breadcrumb مرئي وبيانات منظمة.
- تحسين نصوص الروابط بدل `اقرأ المزيد` المتكرر.
- إضافة أقسام قابلة للزحف في الأرشيف: الماركة، الموديل، السنة، الموقع عند توفرها.
- عدم إنشاء صفحات رقيقة لكل تركيب من الفلاتر.
- ربط الصفحات التحريرية بالكتالوج وبالعروض المناسبة دون حشو كلمات مفتاحية.
- الحفاظ على العربية الطبيعية، وعدم إدخال نصوص مترجمة آليًا غير مراجعة.

## 12. الأداء وCore Web Vitals

يتم تنفيذ SEO والأداء معًا:

- تحديد صورة LCP وعدم تحميلها Lazy.
- إضافة `width` و`height` أو `aspect-ratio` لكل صورة.
- استخدام WebP/AVIF عند توفره مع fallback.
- Lazy-load للصور أسفل الصفحة فقط.
- تقليل CSS وJavaScript غير المستخدم في صفحة السيارة والعرض.
- الحفاظ على CSS الحرج للهيكل الأولي.
- قياس LCP وINP وCLS للصفحة الرئيسية، الأرشيف، السيارة، والعرض.
- تفعيل Cache-Control وETag/Last-Modified بطريقة لا تخزن حسابات أو نماذج شخصية.
- اختبار الهاتف بشبكة بطيئة، وليس سطح المكتب فقط.

## 13. التحليلات والقياس

إعداد Google Search Console وGA4 أو البديل المعتمد، مع قياس:

- الظهور والنقرات والطلبات العضوية.
- الكلمات العربية والإنجليزية.
- النقر على طلب السعر، الحجز، التمويل، واتساب، والمشاركة.
- صفحات 404 والروابط القديمة التي ما زالت تستقبل زيارات.
- نسبة الفهرسة للسيارات والعروض المؤهلة.
- أخطاء Schema وSitemap.
- Core Web Vitals حسب نوع الصفحة والجهاز.

لا يتم إرسال بيانات العملاء أو محتوى النماذج إلى أدوات التحليل.

## 14. خطة التنفيذ المرحلية

### SEO-001 — عقد الفهرسة والقياس | P0

- إنشاء `PublicSeo` مركزي.
- إنشاء `SeoSiteContext` يقرأ اسم الشركة والنطاق واللغة والشعار والوصف من التثبيت الحالي.
- إضافة route classifier موحد.
- تعريف `indexable`, `canonical`, `language`, `entity`, و`image` لكل صفحة.
- إضافة اختبارات HTML أساسية.

**معيار القبول:** لا توجد صفحة عامة قابلة للفهرسة بلا قرار صريح.

### SEO-001A — مولد القيم الديناميكية | P0

- بناء مولد Title وDescription حسب نوع الصفحة.
- إضافة قوالب عربية وإنجليزية قابلة للتخصيص.
- إضافة حقول SEO يدوية للصفحات التي تحتاج صياغة تحريرية.
- وضع حدود للطول، إزالة HTML، ومنع النص الفارغ أو المتكرر.

## 14.5 حالة التنفيذ الحالية

تم تنفيذ طبقة SEO الأساسية داخل الإضافة على مستوى التثبيت الواحد لكل شركة:
