## نتيجة فحص HTTPS المحلي

- Apache يحمّل mod_ssl وملف `httpd-ssl.conf`، ويهيئ المنفذ 443.
- ملف الشهادة المشار إليه في الإعداد المحلي: `C:/xampp/apache/conf/ssl.crt/server.crt`، باسم localhost، دون SAN؛ انتهاء الصلاحية المعلن 8 نوفمبر 2019.
- طلب HTTPS باستخدام curl خارج العزل رفض سلسلة الثقة بـ`SEC_E_UNTRUSTED_ROOT`. هذا فحص فشل، وليس تحققًا ناجحًا من HTTPS. لا يثبت فحص الملف وحده أن العملية الجارية تقدم الشهادة نفسها بعد أي تغييرات خارجية.
- لم تُعدّل إعدادات Apache أو عناوين WordPress، ولم تُعطل مراجعة الشهادة أو تضف استثناء ثقة لإظهار نجاح زائف.

## إعداد staging الجاهز للاستكمال

`apache-https.conf.example` قالب إعداد لمضيف Apache منفصل، مع تحويل HTTP إلى HTTPS وشهادة وسلسلة ثقة ومفتاح خارج Git، وحظر الفهرسة وقيد وصول للمراجعين. يحتاج اسم نطاق ومسارات نسخة staging والشهادة والمفتاح والسجلات وIP المراجع. لا يُنسخ إلى إعدادات الخادم قبل استبدال جميع @@TOKEN@@ ومراجعة PHP وrewrite/proxy والوحدات المطلوبة وتشغيل فحص Apache على المضيف المقصود. القالب لم يُختبر تشغيليًا لعدم توفر تلك المدخلات.

ترتيب التطبيق بعد وصول بيانات الاستضافة:

1. إنشاء نسخة ملفات وقاعدة staging مستقلتين؛ لا تستخدم قاعدة التطوير الحالية كقاعدة إنتاج ولا تشارك بيانات الاتصال بينهما.
2. توجيه DNS والحصول على شهادة صالحة لاسم النطاق وسلسلتها؛ ضبط الوصول المقيد وPHP والمهام والبريد والنسخ والمراقبة.
3. ملء القالب ومراجعة `httpd -t` قبل إعادة تحميل الخادم؛ تحقق من HTTPS دون تجاوز التحقق من الشهادة.
4. ضبط siteurl/home على عنوان staging في قاعدة النسخة وحدها، وتنفيذ استبدال الروابط بأداة تحافظ على serialized data وبعد backup؛ لا تستخدم SQL REPLACE العام على WordPress options.
5. إعادة فحص المحتوى والكوكيز والروابط المختلطة والنماذج وpreflight على الهدف. شهادة HTTPS لا تجعل بيانات التطوير أو النص القانوني غير المكتمل صالحين للإطلاق.

## المتبقي لإكمال النصوص

العنوان المسجل الكامل؛ جدول الاحتفاظ حسب الفئة وسجل الأغراض والمسوغات؛ أسماء وفئات المعالجين ومواقعهم والنقل؛ آلية تحقق الهوية واستقبال الشكاوى ومدتها؛ تفاصيل الضريبة والرسوم والدفع والتسليم وما بعد البيع؛ تاريخ سريان وسياسة تغييرات واعتماد النص النهائي. استخدام Gmail للتواصل أو لطلبات الحقوق يحتاج إدراجه في مراجعة المعالجين وتدفق البيانات؛ لم تُفترض مواقع معالجة أو عقود غير معروفة.

ورقة `../legal/retention-and-processing.csv` تحصر الفئات للمراجعة، ولا تُشغّل الحذف الآلي ولا تقر مددًا أو مسوغات. تعطل الاحتفاظ الآلي الحالي لا يحدد سياسة احتفاظ تجارية دائمة.

## المراجع الرسمية المستخدمة

نطاق المراجعة استند إلى [دليل سدايا لإعداد سياسة الخصوصية](https://sdaia.gov.sa/Documents/PrivacyPolicyGuideline.pdf)، الذي يتناول تحديد المعالجة والاحتفاظ والحقوق. كما رُوجعت [معايير وزارة التجارة للمتاجر الإلكترونية](https://mc.gov.sa/ar/mediacenter/News/Pages/18-08-25-01.aspx) بشأن إظهار البيانات والسياسات. هذه مراجع إعداد، وليست شهادة امتثال لهذا الموقع أو حكمًا بأن كل نشاطه تجارة إلكترونية مكتملة.

قالب TLS مبني على [دليل Apache للـSSL](https://httpd.apache.org/docs/2.4/ssl/ssl_howto.html) و[مرجع mod_ssl](https://httpd.apache.org/docs/2.4/mod/mod_ssl.html)؛ ملاءمته تتطلب التحقق من إصدار الخادم ووحداته وبيئة الاستضافة الفعلية.
