# تنفيذ نظام حقول HTML — النتائج النهائية

**التاريخ:** 13 أكتوبر 2026  
**النطاق:** الموقع العام، حساب العميل، التمويل، تسجيل الدخول، جميع صفحات إضافة AUTO BRANDS المكتشفة، شاشات WordPress المملوكة، المخصص، والوسائط.

## نتيجة المراحل السبع

| المرحلة | التنفيذ |
|---|---|
| 1. الجرد وخط الأساس | أضيف جرد DOM فعلي يستخرج النوع والاسم الميسر والقياسات والتباين وحالة التركيز والتجاوز، مع صور مرجعية متعددة الأحجام. |
| 2. الرموز والطبقة الأساسية | أضيفت رموز دلالية للحقول وطبقة `brand-fields.css` المشتركة للفـاتح والداكن. |
| 3. الواجهة العامة | نُقلت هيئة الحقول المشتركة من ملفات الصفحات إلى الطبقة الموحدة، مع بقاء التخطيط المحلي في القالب. |
| 4. الحساب والتمويل | وُحّدت حقول الدخول والتسجيل والحساب والحاسبة، وأزيل الرسم المحلي غير الضروري لخانات الاختيار. |
| 5. إدارة الإضافة | طُبقت القواعد على `.adc-admin`، ونُظفت القيم المباشرة والتعريفات المرئية المكررة، وحُفظ تمرير الجداول داخل حاوياتها. |
| 6. WordPress والوصول | طُبقت موائمات المخصص والوسائط والدخول والشاشات الأصلية، وأضيفت أسماء ميسرة ورسائل تحقق مرتبطة برمجيًا. |
| 7. التنظيف والتوثيق | أعيد بناء `main.css`، ووُسعت اختبارات المتصفح، ووُثقت طريقة إضافة الحقول والاستثناءات. |

## العقد التقني للحقول

- المصدر الدلالي: `assets/css/brand-tokens.css`.
- الطبقة المرئية المشتركة: `assets/css/brand-fields.css`.
- دعم أخطاء التحقق الأصلية وربط `aria-invalid` و`aria-describedby`: `assets/js/brand-fields.js`.
- نطاقات التطبيق: `.site` و`.adc-admin` و`.adc-admin-native` و`.login`، مع موائمات محددة للمخصص والوسائط في `brand-wordpress.css`.
- الارتفاع المرجعي 44 بكسل، والمقاس الإداري المكتبي 40 بكسل، ويعود إلى 44 بكسل على الشاشات اللمسية.
- تشمل الحالات: default وhover وfocus-visible وreadonly وdisabled وautofill وinvalid وvalid الصريحة وbusy والطباعة.
- تشمل الأنواع: text وsearch وemail وtel وurl وpassword وnumber وdate وtime وdatetime-local وselect وmultiple وtextarea وfile وrange وcolor وcheckbox وradio.
- تستخدم الحقول المنطقية `inline/block`، وتدعم RTL وLTR، و`forced-colors` و`prefers-reduced-motion`.

## إصلاحات بنية HTML

أضيفت أسماء ميسرة للحقول التي كشفها جرد DOM في إدارة العملاء، إلغاء المبيعات، الاستردادات، إعدادات العرض والبائع، والعلامات والمواقع المرجعية. رُبطت ملاحظة كلمة المرور بحقلَي كلمة المرور عبر `aria-describedby`. تولد طبقة التحقق رسالة نصية مرتبطة بالحقل عند فشل التحقق الأصلي، ثم تزيلها بعد تصحيح القيمة من دون المساس بأخطاء الخادم.

حُفظ تقرير الجرد في `.tmp/accessibility-acceptance/form-controls.json`، والصور المرجعية في المجلد نفسه. هذه مخرجات محلية مؤقتة ولا تدخل ملفات النشر.

## إضافة حقل جديد

1. استخدم `label` صريحًا مرتبطًا بـ`for` و`id`، أو ضع الحقل داخل `label` عندما تكون البنية بسيطة.
2. استخدم `aria-describedby` لربط المساعدة أو الخطأ الموجود مسبقًا، ولا تستخدم `placeholder` بديلًا للتسمية.
3. لا تضف لونًا أو حدًا أو حلقة تركيز محلية. استخدم رموز `--ab-field-*` عند وجود اختلاف وظيفي مثبت.
4. اجعل ملف الصفحة مسؤولًا عن Grid وFlex والعرض فقط، واترك الشكل والحالات لـ`brand-fields.css`.
5. استخدم `.is-invalid` أو `aria-invalid="true"` لخطأ الخادم، و`.is-valid` أو `data-valid="true"` للحالة الصحيحة التي يحتاج المنتج إلى إظهارها.
6. استثنِ محرر WordPress وIris والمكونات المركبة عبر موائم محدد؛ لا توسع المحدد العام ليشملها.
7. بعد تعديل القالب، شغّل بناء CSS وفحصه، ثم اختبار الحقول واختبار الوصول.
